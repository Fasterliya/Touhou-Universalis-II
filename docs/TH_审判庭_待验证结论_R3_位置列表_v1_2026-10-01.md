## R3-1 「最近」的距离 / 边界触发器

- **结论**：**可行（且比《脚本规格》预期好得多）**。
  - 《脚本规格》§5 猜的三个名字里，`distance_between` **不存在**、`has_border_with` **不存在**，但**真实的触发器更强**：国家 scope 有 `border_distance_to`，location scope 有 `distance_to` / `distance_to_squared`（各有 `_less_than` / `_greater_than` 变体）。
  - **排序也能做**（不只是过滤）：`ordered_*` 迭代器的 `order_by` 接受引号脚本值，vanilla 已有 `order_by = "unit_location.distance_to(...)"` 实例；`select_trigger` 另有官方文档化的 `pre_evaluation_sort_value`。
  - 退路"实力最强者"同样有现成蓝本（`ordered_international_organization_member` + `order_by = military_strength`）。

### 证据（关键原文摘录）

**① 国家间距离 —— 块触发器形式：**
`VANILLA\common\scripted_relations\alliance.txt:204-212`
```
                scope:recipient = {
                    border_distance_to = {
                        country = scope:actor
                        value < 150
                    }
                    relative_strength = {
                        target = scope:actor
                        value < 0.60
                    }
                }
```
→ **`border_distance_to` 的块形式参数名是 `country`，比较写在 `value` 上。** 这一段同时给了"距离 + 相对实力"两个判据的官方组合范例，几乎就是代理人选取所需。

**② 国家间距离 —— 引号脚本值形式：**
`VANILLA\events\wokou_events.txt:7`
```
		"border_distance_to(root)" < 800
```
`VANILLA\common\generic_actions\golden_age_of_piracy.txt:240`
```
			value = "scope:actor.border_distance_to(scope:target_country)"
```
→ **引号形式可在比较式左侧，也可在 `value =` 里。**

**③ 地块距离 —— 块触发器形式：**
`VANILLA\common\script_values\building_caps.txt:825-832`
```
	if = {
		limit = {
			distance_to_squared = {
				location = location:rome
				value >= 75000
				value < 85000
			}
		}
```
→ **location scope 上的块参数名是 `location`。**（对比 ① 的 `country` —— 两个字段的参数名不同，易错。）

**④ 排序（不止过滤）—— 决定性证据：**
`VANILLA\events\DHE\flavor_chi_treasure_expedition.txt:2549-2553`
```
			ordered_army = {
				order_by = "unit_location.distance_to(scope:expedition_initiator.var:chinese_treasure_fleet_location)"
				max = 1
				save_scope_as = target_unit
			}
```
→ **`order_by` 接受带 `distance_to` 的引号脚本值**，`max = 1` 取最近的一个。这直接证明"按距离排序取最近"在 EU5 语法层是成立的。

**⑤ 排序 —— 实力维度的官方范例（退路蓝本的现成模板）：**
`VANILLA\common\situations\war_of_religions.txt:49-64`
```
			ordered_international_organization_member = {
				limit = {
					is_protestant = yes
					is_subject = no
				}
				order_by = military_strength
				max = 1
				check_range_bounds = no
				create_international_organization = {
					type = international_organization_type:protestant_union
					add_country_to_international_organization = prev
					set_leader_country = prev
				}
				international_organization:protestant_union = { set_leader_country = PREV }
				save_scope_as = protestant_union_leader
			}
```
→ **这一段就是"从 IO 成员中选一个最强/最合格的当领袖"的完整官方实现**：`limit` 筛合格候选 → `order_by` 排序 → `max = 1` → `save_scope_as`。`ordered_international_organization_member` 在 vanilla 中另有 20+ 处用例（`VANILLA\common\situations\sengoku.txt:50,58,97,136,175,214`、`VANILLA\common\international_organizations\hre.txt:480`、`VANILLA\common\scripted_effects\situation_effects.txt:877-1033`）。

### 语义边界与坑

1. **参数名不统一**：`border_distance_to` 块内用 `country =`；`distance_to*` 块内用 `location =`。写错不报错但静默不匹配，是高风险坑。
2. **`distance_to` 是 location→location，不是 country→country**。要"两国距离"必须落到首都或具体地块：
   - 首都距离：`"capital.distance_to(prev)"`（`VANILLA\events\wokou_events.txt:27` 实例）
   - 或直接用 `border_distance_to`（它才是国家维度的）
3. **`border_distance_to` 的语义是"国境间最短距离"，不是"首都间距离"**。两者对"地缘最近"的直觉可能不同 —— 对代理人选取，`border_distance_to` 更符合"邻国领衔"的设计意图。
4. **`distance_to_squared` 不可与 `distance_to` 的阈值混用**：平方后数值量级完全不同（`building_caps.txt:829` 的阈值是 75000 这个量级）。做排序键可互换（单调性一致），做阈值判定必须换算。
5. **`is_neighbor_of` 在 location scope 上的方向**：`location = { is_neighbor_of = country }` 合法（`succession_crisis.txt:753`），但反过来 `country = { is_neighbor_of = location }` 未见先例。**统一在国家 scope 上用**。
6. 【不确定】`order_by = "border_distance_to(scope:X)"` 这个**具体组合**在 vanilla 无逐字先例（现有先例是 `ordered_army` + `distance_to`）。`ordered_*` 四前缀同族（`WIKI/Scope` 迭代器表），推断成立，但**必须实机验证一次**。若失败，退 `order_by = military_strength`（有逐字先例）。
7. **`any_neighbor_country` / `any_border_location` 等迭代器名来自 `WIKI/Scope` 的迭代器总表**（非本地文件），属 wiki 级证据（第 2 优先级）。`any_neighbor_location` 已有项目内先例（`th_gensokyo_feast.txt:65`）可交叉佐证。
8. **性能**：`"border_distance_to(...)"` 每次求值都要算国境距离；`VANILLA\common\generic_actions\parliament.txt:449` 的注释提示了一次缓存代价的量级：
   ```
   							value = "border_distance_to(scope:actor)" # capital location only — one cache lookup vs O(locations_per_province)
   ```
   → **排序键上用它只算一次/候选国**，可接受；但不要放进每月每国遍历的深处。

### 退路

- **一级退路**：`order_by = military_strength`（逐字先例 `war_of_religions.txt:54`）→ 即《脚本规格》§5 表格第 4 行的"实力最强者"，**零风险**。
- **二级退路**：`order_by = total_locations_owned`（`italian_wars.txt:371` 的 `sort_global_variable_list` 官方排序键）→ "体量最大者"。
- **三级退路**：合格候选中无满足硬门槛者 → `relative_strength` 放宽到 `>= 0.8` → 仍无 → 三贤者中 `ordered_international_organization_member` + `order_by = military_strength`。**永不为空**（与《脚本规格》§5 兜底链一致，且全部有蓝本）。

## R3-2 全局变量列表：写入 / 遍历 / 归属回查

- **结论**：**可行（遍历写法存在，且比预期更完整）**。
  - (a) 遍历写法 **存在**，但**不是** `every_global_variable_list`（该名不存在）。真名是 **`every_in_global_list = { variable = <列表名> ... }`**，同族还有 `any_` / `ordered_` / `random_`。
  - (b) 循环体内 `this` = 列表元素（location 时可直接取 `.owner` / `is_core_of`），`prev` = 外层 scope，`root` = 基础 scope。
  - (c) 判归属用 **`owner = scope:X` / `owner = c:TAG`**；**`is_owned_by` 不存在**。
  - (d) `previous_owner` 可用但**必须守卫**（vanilla 自己就守）；6 个月跨度**不保证可靠**，退路是立案时快照进变量。
  - (e) 项目注释"`save_scope_as` 跨 scripted_effect 不可靠"—— **核实为正确**，vanilla 自己的注释就在做同样的重定位。

### (a) 遍历 global variable list 的合法写法

**不存在**：`every_global_variable_list` / `any_global_variable_list` / `ordered_global_variable_list` / `random_global_variable_list` / `every_in_global_variable_list` / `global_variable_list_member` —— `GAMEROOT` 全库 grep 上述全部名字 = **0 命中**。

**真实写法**（`every` / `any` / `ordered` / `random` × `_in_list` / `_in_local_list` / `_in_global_list` 共 12 个）：

`WIKI/Scope` §"Trigger iterators" 的迭代器表给了权威的键名区分：
```
any_in_global_list | Iterate through all items in global list. | any_in_global_list = {
 list = name / variable = name
 <count=num/all> / <percent=fixed_point>
 <triggers>
}
Use "list" for lists created by add_to_(temporary)_list
Use "variable" for lists created by add_to_(global/local)_variable_list | none |
```
→ **`add_to_global_variable_list` 建的列表，读取键必须是 `variable =`**（不是 `list =`）。这是本项目最易踩的坑。

四种前缀的语义（`WIKI/Scope` §Iterators）：
```
| any_<name>     | Trigger scope, checks that any returned scope returns true for contained triggers. Can use count <operator> <scripted value> or percent ... With count = all ... requires all scopes to return true |
| every_<name>   | Effect scope, executes effects on all returned scopes. Can use limit = { <triggers> } |
| ordered_<name> | Effect scope, executes effects on returned scope ... order_by = value ... position = int ... min / max ... check_range_bounds = no |
| random_<name>  | Effect scope, executes effects on a single random returned scope ... weight = { mtth_blocks } |
```

**vanilla 实例（列表是 location 的，最贴近本项目）：**
`VANILLA\events\hre.txt:1150-1164`
```
		ordered_in_global_list = {
			variable = hre_conquered_province_list
			order_by = population
			position = 0
			save_scope_as = conquered_location
		}
		every_in_global_list = {
			variable = hre_conquered_province_list
			root = {
				change_variable = {
					name = hre_pop_percentage_addition
					add = prev.population
				}
			}
		}
```
→ 同时给出：列表名 `hre_conquered_province_list` 在 `VANILLA\common\on_action\_hardcoded.txt:2367` 由 `add_to_global_variable_list = { name = hre_conquered_province_list ... }` 填充；`every_in_global_list` 内 **`prev.population` 取外层 scope**、**`root = { }` 跳回基 scope**。

**另一实例（`any_in_global_list` 触发器形式）：**
`VANILLA\common\situations\italian_wars.txt:406-412`
```

			limit = {
				any_in_global_list = {
					variable = iw_foreign_leagues_list

				}

→ **证明遍历体内可写任意触发器，含 `?=` 空链接守卫。**

**排序专门的 effect：** `sort_global_variable_list`
`VANILLA\common\situations\italian_wars.txt:368-373`

### (d) `previous_owner` 的语义与生命周期

**语义：** location scope 上的一个 **link（国家引用）**，指向"该地块上一位拥有者"。官方 on_action 文档把它映射成 ownership 变更钩子的 `scope:loser`：
`WIKI/On_action` §"List of on actions"
```
on_location_changed_owner | root = location, scope:loser = previous owner, scope:winner = new owner |
```
本地对应实现 `VANILLA\common\on_action\_hardcoded.txt:4204-4207`

**生命周期：`【不确定：未找到权威定义何时被覆写/清空】`。** 已查范围：
- `VANILLA\common\trigger_localization\` 全目录（无 `previous_owner` 条目 —— 它是 link 不是 trigger）
- `VANILLA\common\effect_localization\` 全目录（无）
- `KB\reference_official_defines\` 全树 grep `previous_owner` = **0 命中**
- `WIKI/Scope`、`WIKI/On_action`（无明确表述）
- `WIKI/Variables` 页 **不存在（HTTP 404）** —— 见 R3-3

**但"不可靠"这一点有强间接证据 —— vanilla 自己就不信任它：**
1. **存在性守卫**：`VANILLA\common\country_interactions\hre.txt:2079` —— `exists = previous_owner`（说明可能为空）
2. **国家存活守卫**：同处 `:2084` —— `country_exists = previous_owner`（说明**可能指向一个已灭亡的国家**；这一点对本项目尤其关键，因为被吞并国家的 `previous_owner` 就是死国）
3. **时间跨度守卫**：`VANILLA\common\events\situations\hundred_years_war.txt:701` —— `NOT = { previous_owner = c:FRA }`，用在战争结束后的判定里，说明跨事件读取时它在 vanilla 也需要防
4. **项目自身的写法**（`MOD\in_game\common\scripted_effects\th_gensokyo_crusade_effects.txt:133-140`）已带 `exists` + `country_exists` 双守卫，**方向正确**

**判据：对"立案 → 6 个月后回查"这个时间跨度，`previous_owner` 不可靠。** 理由：
- 它表达的是"**上一任**拥有者"，不是"**被扩张前的**拥有者"。若这 6 个月内该地块被转手两次（A→B→C），`previous_owner` 指向 B 而非 A，而设计要的是 A（受害国）。
- 它没有"沿链条回溯"的语义，也没有"保留 n 年"的语义。

**退路（推荐，且完全可行）：立案时把 `previous_owner`（或 `scope:loser`）快照进变量，观察期末读变量而非读 link。**
关键优势：**location 是持久游戏对象，存进 global variable list 或 `set_variable value = <location>` 不会因 scope 失效而丢** —— 这正是绕开 `save_scope_as` 寿命问题的正确设计。

### (e) `save_scope_as` 的作用域 / 寿命

**核实项目注释："`save_scope_as` 跨 scripted_effect 均不可靠" —— 正确。**

**最强证据（vanilla 自己在做同样的重定位，并写明理由）：**
`VANILLA\events\DHE\flavor_chi_treasure_expedition.txt:90`

```
→ vanilla 注释原文 **"Reset the first country's scope in case it's been lost"**（重置第一个国家的 scope，以防它已丢失）。**"已丢失"是被官方脚本承认的常态**，不是本项目特有的 bug。

同文件 `:91` 起的后续段落每个 effect 入口都重新 `save_scope_as`，与项目 `th_gensokyo_crusade_effects.txt:148-150` 的注释"效果内重定位"完全同构。

**`save_scope_as` vs `save_temporary_scope_as`：**
- 两者都存在于 vanilla：`save_temporary_scope_as` 在 `VANILLA\common\scripted_effects\` 下 19 处，如 `country_effects.txt:608,762,942,1015,2319,2525,2595`、`situation_effects.txt:373,805,1196`、`international_organization_effects.txt:132,134,304,369,372,452,453,862`、`religious_effects.txt:259`
- `international_organization_effects.txt:452-453` 连用两行，显示二者并存：
  ```
  	$international_organization$ = { save_temporary_scope_as = source_io }
  	save_temporary_scope_as = member_state
  ```
- **官方对二者差别的明文定义：未找到。** 已查范围：`KB\reference_official_defines\` 全树 grep `save_scope_as|save_temporary_scope_as` = **0 命中**；`KB\reference_official_defines\changes_script_docs.md` grep `scope_as` = **0 命中**；`VANILLA\common\on_action\on_actions.info`（只说明 on_action 内 `effect` 设的 scope "不会带到它触发的事件里"）；`WIKI/Scope`（只讲 `root` 与 `saved scope` 用 `scope:` 引用，未定义寿命）；`WIKI/Variables` **404**。
- 【不确定，推断】按 Jomini 通例及命名，`save_temporary_scope_as` 寿命更短（限于当前效果链/当前 tick），`save_scope_as` 寿命更长（可跨事件，但跨 scripted_effect / 跨延迟仍会被回收）。**本轮无蓝本可证，标为不确定。**

| `GAMEROOT` 全库 `global_var:` 引用 | 全局变量命名空间的引用点 | **61 处**（`grep` 报 "Found 61 matches"），跨 `timur_character` / `wallensteins_prison` / `saint_george_bank_tag` / `chinese_treasure_voyage_running` 等约 10 个全局变量 |

**判断依据（是否值得冒风险）：值得，理由三条：**

1. **量级对比**：本项目计划约 20 个国家变量；vanilla 单文件即用到约 60 个不同变量名，且 `global_var:` 命名空间是**全局单表**（所有国家共享一个命名空间）也有 10+ 个在用。**20 个 per-scope 哈希项，在量级上远低于 vanilla 自身用量**，撞上限的概率极低。
2. **真正的风险不是"上限"，是三件已确知的事**：
   - ① **读前必加 `has_variable` 守卫**（项目铁律 11，`th_gensokyo_io_chain_values.txt:81-91` 实证"Value of wrong type 'none'"）—— 这是已踩过的坑，比上限真实得多。
   - ② **`ai_will_do` 不可读变量**（项目铁律 5，运行时实证）—— 直接决定了《脚本规格》§1.1 的"独立标记方案"是**必要**的，不是可选优化。
   - ③ **存档膨胀**：每国 20 个变量 × N 国（EU5 全局数千国）会进入存档。但 vanilla 自身就在这么做，且 `set_variable` 的 timed 形式会自动回收（见 R3-4d），**可控**。
3. **没有"上限"证据 ≠ 有上限**。引擎用的是 per-scope 键值容器，Paradox 从未文档化 cap。**不建议为规避一个未证实的上限而预先重构数据结构。**

### 可直接复制的写法

无（该项为 FAILED）。

**但有一条来自 R3-4d 的降本建议**：能用 **timed variable** 表达的"倒计时/免疫期"，就不要用"数值 + 每月减法"。前者到期自动消失，**少一个长期驻留的数值变量 + 少一段每月 effect**：

### 判定处：有变量 = 在免疫期内；变量自动消失 = 免疫期结束
NOT = { has_variable = th_gensokyo_sanction_immunity }
```
（语义依据见 R3-4d 的 `decline_of_majapahit_timer` / `ccw_timer` 实例。这一条能直接把《脚本规格》§2 变量总表里的若干"数值 + 标记"双字段**合并成单字段**。）

## R3-4 国家月度脉冲的载体与性能

- **结论**：**可行，且发现一个比"每月减法"更省的官方载体。**
  - (a) 项目现有写法：**追加到 vanilla 的 `monthly_country_pulse` 的 `on_actions` 列表**里，不是 `random_events`，也不是 `every_country` 遍历。
  - (b) vanilla 的每国月度钩子共 **7 个**（下表）；**`trigger` 为假时整个 on_action 不执行**（官方明文）。
  - (c) 推荐：**保持 `monthly_country_pulse`**（唯一真正的"每国每月"钩子），但把 `trigger` 做成最廉价的单变量判定；**若审判庭能改成 situation，则 `situation.on_monthly` 是全局每月一次，便宜一个数量级**。
  - (d) vanilla 的惯用倒计时写法是 **`set_variable = { name = X value = yes months/days/years = N }`（timed variable，到期自动消失，用 `NOT = { has_variable = X }` 判定到期）**，而不是每月减法。

**"是只在有 trigger 通过时才跑 effect 吗？" —— 是，官方明文：**
`VANILLA\common\on_action\on_actions.info:2`（= `WIKI/On_action` §"On action structure"）
```

		trigger_conditions = yes
	}
```
→ **`trigger` 求值不可避免（每国每月一次），但 `effect` 可被跳过。** 因此性能优化的着力点是**让 `trigger` 尽可能廉价**。

**并行化（官方明文的性能指引）** —— `VANILLA\common\on_action\on_actions.info` 的对应段落 / `WIKI/On_action` §"Parallelisation"：

```
→ **官方建议：与其在 on_action 的 `effect` 块里做重活，不如 `trigger` 筛完后用 `trigger_event` 到事件里做**（事件块是并行化的，`effect` 块不是）。

### (c) 对"每档 6 个月倒计时 + 观察期末判定"的载体推荐

**推荐：`monthly_country_pulse`（保持现状）+ 廉价 trigger + timed variable 判定。** 理由与更省的写法：

**方案 A（推荐，改动最小）—— 保持 `monthly_country_pulse`，但把 trigger 改成单变量判定：**
```eu5
monthly_country_pulse = {
    on_actions = {
        th_gensokyo_tribunal_observation_pulse
    }
}

th_gensokyo_tribunal_observation_pulse = {
    ### 只用最廉价的一个 has_variable 作为门；不做 IO 成员查询
    trigger = {
        has_variable = th_gensokyo_under_observation
    }
    effect = {
        th_gensokyo_tribunal_observation_check_effect = yes
    }
}
```
- **为什么比现状更省**：项目现在的 `trigger = { is_member_of_international_organization = international_organization:th_gensokyo_io }` 要**对全世界每个国家每月做一次 IO 成员查询**；改成 `has_variable` 后，绝大多数国家是一次哈希查空即返回。被观察国是极少数（同时最多几国）。
- **为什么不用 `country_pulse_for_high_infamy`**：它是"高恶名"专用语义（`VANILLA\common\on_action\country_pulse_for_high_infamy.txt`），借用会让 hook 语义混淆，且其筛选条件不由本项目控制。**不建议借用。**

**方案 B（更省，但需设计变更）—— 把审判庭做成 situation，用 `situation.on_monthly`：**
`VANILLA\common\situations\readme.txt:13`（官方文档）
```
# on_monthly = <effect> effect every month (root = situation)
```
实例：`VANILLA\common\situations\italian_wars.txt:386`（`on_monthly = { ... }`）、`VANILLA\common\situations\council_of_trent.txt:91`、`VANILLA\common\situations\war_of_religions.txt:98`（全库 20+ 处）。
- **性能差一个数量级**：`on_monthly` 是**全局每月一次**（root = situation），而不是"每国每月一次"。国家数 3000 时，这是 3000 倍差距。
- **代价**：审判庭目前的载体是 IO（`international_organization:th_gensokyo_io` + 独立 `th_gensokyo_tribunal` IO）。**IO 定义里没有 `on_monthly`** —— `VANILLA\common\international_organizations\` 全目录 grep `on_monthly|on_yearly|on_biyearly|on_four_yearly|on_activate|on_deactivate` = **0 命中**。所以走这条路需要把"观察期"从 IO 挪到一个 situation 上。
- **判定**：**这是设计层的取舍，建议交用户拍板**（见第 4 节冲突项）。若审判庭只需"每 6 个月推一档"而非"每月检查"，方案 A 的 `biyearly_country_pulse` 甚至已够用。

**方案 C（最省，且能顺带解决 R3-2d）—— 用 `on_location_changed_owner` 事件驱动替代轮询：**
`VANILLA\common\on_action\_hardcoded.txt:4204`（`on_location_changed_owner`，scope: root=location, `scope:loser`=原主, `scope:winner`=新主）
- 思路：立案时把涉案地块登记进 global variable list；此后**不轮询**，而是**在地块易主时被动检查**"这块地是不是涉案地块 + 新主是不是受害国"，全归还则立即结案。
- 优点：观察期内零月度开销；反应即时（不必等到月末）。
- 缺点：仍需一个月度脉冲做**超时**判定（6 个月到点未归还 → 升档）。所以是"C + A 组合"。

**最终推荐：方案 C + A 组合。** 即：
1. 日常：`on_location_changed_owner` 被动检查归还（事件驱动，零轮询）
2. 到期：`monthly_country_pulse` + `has_variable` 廉价 trigger 检查 timed variable 是否消失

### (b) `international_organization:` 前缀的使用规则

**官方明文（最高证据）** —— `VANILLA\common\international_organizations\readme.txt:182`（与官方转储 `KB\reference_official_defines\types\international_organizations.txt:182` 逐字一致）：
```
# - international_organization:<type_tag>: sets the scope to the international organization of the supplied unique type (doesn't work for non-unique types as there could be more than one of them)
```
→ **规则：`international_organization:<tag>` 只对 `unique`（全局唯一）类型有效。非唯一类型（可以同时存在多个实例）不能用这个前缀 —— 因为无法确定指哪一个。**
→ **本项目 `th_gensokyo_io` / `th_gensokyo_tribunal` 必须是 unique 类型，该前缀才成立。** 这是铁律 10 没说出口的**前置条件**，建议补上。

**vanilla 中观察到的前缀形态（8 类）：**

| 形态 | 实例 |
|---|---|
| scope 块 | `VANILLA\common\events\hre.txt:1143` —— `international_organization:hre = {` |
| 存在性判定 | `VANILLA\common\on_action\country_monthly.txt:1167` —— `exists = international_organization:hre` |
| trigger 参数（country → IO） | `VANILLA\common\on_action\country_monthly.txt:112` —— `is_member_of_international_organization = international_organization:catholic_church` |
| effect 参数 | `VANILLA\events\situations\sengoku.txt:119` —— `destroy_international_organization = { target = international_organization:japanese_shogunate }` |
| link `.leader_country` | `VANILLA\common\events\hre.txt:1144` —— `leader_country.ruler ?= { save_scope_as = hre_ruler }`；`VANILLA\events\situations\hussite_wars.txt:39` —— `country_exists = international_organization:hre.leader_country` |
| link `.var:X` | `VANILLA\common\country_interactions\hre.txt:1726` —— `value = international_organization:hre.var:imperial_authority` |
| link `.total_members` / `.international_organization_population` | `VANILLA\events\hre.txt:537`；`VANILLA\common\situations\sengoku.txt:52` |
| 比较式 | `VANILLA\common\events\situations\italian_wars.txt:121` —— `this = international_organization:italian_league_1` |

**何时必须加 / 何时不能加：**
- **必须加**：从任意非 IO scope 跳到某个 **unique** IO 时（`international_organization:hre = { ... }`、`exists = ...`、当 trigger/effect 的参数）。
- **不能加**：目标是**非 unique** 类型时（改用 `any_international_organizations_member_of` 迭代器或 `scope:`）；以及 `international_organization_type:<tag>` —— 那个是**类型值命名空间，不是 scope 访问器**。
  - 证据：全库 grep `international_organization_type:[a-z_0-9]+\.`（带链接/块的形态）= **0 命中**；`international_organization_type:hre = {` 亦 **0 命中**。
  - 它的合法用法只有比较/参数：`VANILLA\common\scripted_triggers\international_organization_triggers.txt:54` —— `limit = { international_organization_type = international_organization_type:hre }`；`VANILLA\common\trigger_localization\international_organization_triggers.txt:223` 定义该 trigger。
  - 官方法档也把它列为 trigger 而非 link：`KB\reference_official_defines\types\international_organizations.txt:153` —— `# - international_organization_type: checks if the organization is of the supplied type`

**【不确定】** `.var:` 点号形式在 catholic_church 上无 vanilla 先例（全库 grep `catholic_church\.var:` = **0 命中**）。已在 `hre` 与 `middle_kingdom` 上证实（`VANILLA\common\script_values\io_policy.txt:581`、`VANILLA\common\generic_actions\middle_kingdom.txt:130`）。**建议本项目统一用块形式 `international_organization:X = { var:Y ... }`（两种 IO 都有先例，最稳）。**

### 语义边界与坑

1. **`change_location_owner` 不自动改 `integration_level`** —— 必须补 `change_integration_level`（`hre.txt:2094-2099`）。**本项目当前缺失此步。**
2. **国家不存在时的行为未定义**：`country_exists` 守卫是 vanilla 的通行做法，**本项目必须保留**（`th_gensokyo_crusade_effects.txt:138` 已有）。
3. **`create_country_from_cores_in_our_locations` 的参数必须是国家**，`= yes` 会报 `scope type boolean, expected country`（项目已实证，本报告核实其正确）。**"释放全部"无直接等价语义。**
4. **复国依赖 core**：`create_country_from_cores_in_our_locations` 只能从**已存在的 core** 建国，所以**必须先 `add_core`**（`flavor_mol.txt:229`）。
5. **`source_global_list` 的列表元素类型必须与 `looking_for_a` 匹配**：`looking_for_a = location` 配 location 列表。**若列表里混了国家（如 R3-2 建议的"地块+受害国同表"），`source_global_list` 会出问题** —— 所以**建议把"涉案地块列表"与"受害国"分开存**（受害国用 `set_variable` 或独立列表），不要混表。
6. 【不确定】`change_location_owner` 对**已灭亡国家**的行为（见 (a)）。

### 退路

- **交还领地**：若 `change_location_owner` 对某些地块失败 → 退 `change_location_owner_forcefully`（`location_effects.txt:120`，语义更强）。
- **复国**：若 `create_country_from_cores_in_our_locations` 行为不可控 → 退为**只做"归还领地 + 补核心"**（`add_core` 单独可用，让该国在原主手里"有核心但不存在"），等它被其他机制复国。设计上仍成立（《实施计划》已标注"实现较绕，可后置"）。

### 对《脚本规格》/《实施计划》的影响

- ✅ **《实施计划》履约条目 3（"释放被吞并的国家"，标注"实现较绕，可后置"）→ 可升级为"可行"**。**约束：只能释放"指定的"国家，不能"释放全部"。** 建议把该条目的语义定为"**释放本次判决涉及的特定被吞并国家**"，即可落地。
- ⚠️ **《脚本规格》§6.1 :281 与 §6.2 :288 的列表设计需微调**：涉案地块列表**只装 location**，受害国另存（否则 R3-6c 的 `source_global_list` 不能直接复用该列表）。这是一处**跨 R3-2 / R3-6 的一致性要求**。
- ⚠️ **`th_gensokyo_trial_return_lands_effect`（`th_gensokyo_crusade_effects.txt:111-143`）建议补 `change_integration_level` 修正**（回到 `integrated`），否则归还的地块整合度不对。
