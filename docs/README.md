## 阅读顺序

1. 《设计定案》第 1–4 章 —— 不看定位与流程总图，后面全是细节噪音；
2. 《实施计划》第 1 章 —— 确认改动面与保留面；
3. UI 相关看《UI规格》；
4. **要动代码就看《脚本规格》** —— 写法铁律 17 条、变量与标记总表、逐行动的字段规格都在那里；
5. **动代码前必须先过《实施计划》第 4 章与《脚本规格》第 9 章的待验证项** —— 两份清单合并使用，其中"GUI 分流"与"制裁修正字段"不通会导致返工。

## 命名与写作约定

- 文件名：`TH_<系统>_<文档类型>_v<版本>_<日期>.md`
- 结论标分级：**【定案】**（已拍板）/**【待拍板】**（等用户决策）/**【待验证】**（等回蓝本或实机确认）
- 引用脚本一律写成 `相对路径:行号`，便于回查；未验证的行号写"约"或不写
- 不写"看起来合理"的语法 —— EU5 语法一律以蓝本 + base game 为准，本文档不承担语法判定职责
