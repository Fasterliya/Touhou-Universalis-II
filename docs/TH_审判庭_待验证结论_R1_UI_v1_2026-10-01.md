## R1-1 面板分流机制（阻塞全部 UI）

- **结论**：**有条件可行** —— 且**机制与设计文档的假设不同**。Vanilla 的分流不是"GUI 里按 IO 类型判定"，而是 **`gui/panels/organization/<IO类型key>.gui` 一文件一类型**（引擎按当前 IO 的类型 key 加载同名 GUI 文件）。设计文档的方案 A / B **都不需要**；但**"整份 override `panel_content`"这一做法是错的**（见 R1-2）。

- **证据**：

  **① 类型/模板 - 实例的三层结构（GUI 基座）**

  - `VANILLA\gui\panels\organization\common.gui:614-615` —— `type organization_panel = widget {` / `name = "organization_panel"`

  **④ base game 如何让 HRE 面板与教皇面板不同**
  - 机制 = **文件分流 + 文件内无条件 override**，不是"数据在别的 IO 上为空"。
  - 决定性证据：`hre.gui` 全文 **0 处** `GetNameKey`（在 `hre.gui` 内 grep `GetNameKey` 无匹配；仅在 `:333/341/345/349/484/488/492/500` 有**被注释掉**的 `InternationalOrganizationTypeVariable.GetTag`）。→ HRE 的 300+ 个 `blockoverride` **没有任何 IO 类型条件**，纯粹因为引擎只为 `hre` 类型加载 `hre.gui` 才不串台。
  - `hre.gui` 的 override 是**点状覆盖命名 block**，不是整份替换：`:746` —— `blockoverride "ios_information_header_visible" { visible = no }`；`:27` —— `blockoverride "organization_panel_left_header" {`；`:1840` —— `blockoverride "organization_panel_members_area" {`；`:2467-2469` —— `blockoverride "organization_candidates_tab_visible" { visible = no }`。

  - "文件分流 + visible 判定"**也是** vanilla 同款，只是用在**共享文件** `common.gui` 内部：`common.gui:177/185/199/345/535` 均在 `panel_content` 内按 `GetNameKey` 切换默认主题的呈现。→ 两种都是 vanilla 做法，**文件分流是主用法**。

  **⑤ 复核你的 grep：`hre.gui` 里确实没有 `blockoverride "panel_content"`**
  - 在 `VANILLA\gui\panels\organization\hre.gui` 内 grep `panel_content` → **No matches found**。你的判断正确。
  - 对比：`MOD\in_game\gui\panels\organization\th_sages_council_io.gui:6-7` —— `organization_panel = {` / `blockoverride "panel_content" {`，是全仓库**唯一**一处顶层 `organization_panel`（在 `MOD\in_game\gui` 下 grep `^\s*organization_panel\s*=` 只有这一处）。
  - → **vanilla 从不整份替换 `panel_content`；MOD 目前是全球唯一的例子。** 这正是 R1-2 那个"分页丢了"的根因。

- **可直接复制的写法**：

  **主方案（vanilla 同款）**：一个 IO 类型一个文件，文件名 = 类型 key。只覆盖需要的命名 block，**不动 `panel_content`**。

  `MOD\in_game\gui\panels\organization\th_gensokyo_tribunal.gui`（新建）：
  ```
  organization_panel = {
      # 只覆盖需要的命名 block —— 其余（宝库分页/成员/议会/候选…）全部保留
      blockoverride "organization_panel_left_header" {
          # 关系图三段（彼岸 → 代理人 → 罪人）放这里或自家 block
      }
      blockoverride "organization_panel_extra_item" {
          # 总览底部追加案卷卡（T2）
      }
      blockoverride "organization_overview_tab_visible" {
          visible = "[InternationalOrganizationsView.Vars.NotExistOrHasValue( 'organizations', 'overview' )]"
      }
  }
  ```
  `MOD\in_game\gui\panels\organization\th_gensokyo_io.gui`（**当前整份被 `#` 注释掉，必须先恢复一个顶层 widget，否则该类型的面板无文件可用**）：
  ```
  organization_geodiplomatic_theme = {
      blockoverride "organization_panel_overview_visible" {
          visible = "[InternationalOrganizationsView.Vars.NotExistOrHasValue( 'organizations', 'overview' )]"
      }
      # 案卷区（T2）追加在此
  }
  ```
  `MOD\in_game\gui\panels\organization\th_human_village_io.gui`（新建，可先空实例以显式声明用默认面板）：
  ```
  organization_panel = {}
  ```
  `MOD\in_game\gui\panels\organization\th_sages_council_io.gui`（**保留文件名，但删掉 `blockoverride "panel_content"`**，改为点状覆盖；理由见 R1-2）

  **退路方案（如果实机证明按文件名分流不成立）**：把类型判定写在共享文件里，用 vanilla 同款表达式：
  ```
  visible = "[EqualTo_string(InternationalOrganizationsView.GetInternationalOrganization.GetType.GetNameKey,'th_gensokyo_tribunal')]"
  visible = "[Not(Or3(EqualTo_string(InternationalOrganizationsView.GetInternationalOrganization.GetType.GetNameKey,'th_gensokyo_io'),EqualTo_string(InternationalOrganizationsView.GetInternationalOrganization.GetType.GetNameKey,'th_sages_council_io'),EqualTo_string(InternationalOrganizationsView.GetInternationalOrganization.GetType.GetNameKey,'th_human_village_io')))]"
  ```
  （即设计文档的方案 A —— vanilla 在 `common.gui:177/185/199` 就是这么写的，所以方案 A 本身是**有蓝本支持的**，只是它不是主用法。）
  方案 B（IO 变量）**不需要**，可作为二层保险。

- **语义边界与坑**：
  1. **文件名必须等于类型 key**。任何别的名字（如 `th_shared_io.gui`）在按名加载假设下**不会被加载**。
  2. `blockoverride` 只能覆盖**实例化树里已存在**的 block。整份替换 `panel_content` 之后，`common.gui:5-658` 里的所有子 block（宝库分页、候选、法律、决议、枢机、派系、圣徒、议会、成员、overview）**全部消失**，此时再写 `blockoverride "organization_treasury_tab_visible"` 是**无效的**（目标 block 已不在树上）。
  3. `visible` 与 `enabled` 可分开写（`hre.gui:2471-2474` 就是 `visible = yes` + `enabled = "[Or(...GetPayments... , ...IsCurrencyEnabled('gold'))]"`）。
  4. **对其他 mod / vanilla 的副作用**：按名加载下，MOD 里名为 `th_*` 的文件只影响 `th_*` 类型，**不碰 vanilla 与其他 mod 的 IO**。反过来，若某 mod 也定义了同名的 `th_gensokyo_io` 类型 key，那就是类型 key 冲突（加载顺序 last-wins），与 GUI 无关。
  5. **【不确定】** `MOD\in_game\gui\panels\organization\th_gensokyo_io.gui` 目前**存在但内容全被注释**（`:1` = `# organization_panel = {`）。"文件存在但无顶层 widget"的行为未验证（可能回退默认、也可能报错/空面板）。建议先按上面的写法恢复一个真 widget。

- **退路**：
  - 若按名分流被实机否定 → 方案 A（`GetNameKey` visible 判定，vanilla `common.gui:177` 同款）。
  - 若方案 A 也失败 → 方案 B（IO 变量 + `GetVariable.IsSet`，项目已在 `th_sages_council_io.gui:114-119` 大量使用该写法）。

- **对《脚本规格》/《实施计划》的影响**：
  - 《UI规格》§1.2 的**方案 A 与 B 均非必要**；新增"方案 0：一类型一文件（主用法）"。
  - 《UI规格》§1.1 的**推论"点开审判庭会看到贤者议会那一套"很可能是错的**（`th_sages_council_io.gui` 的名字正好等于贤者议会的类型 key → 只对贤者议会产生作用）。实机确认步骤应改为："点开审判庭 IO，若看到 **vanilla 默认 IO 面板**（而非贤者布局），即证实按名分流"。**这一条与设计文档的预期相反，务必先做这 30 秒验证。**
  - 《UI规格》§1.1 表格里"整份替换 `organization_panel`，且未按 IO 类型分流"这一行的定性与"内容无条件渲染"的结论需要修正：它**确实未做类型判定，但也不需要做**。
  - 《实施计划》§4 待验证 1（阻塞 UI 全部）→ **可关闭**（改为实机 30 秒确认）。

## R1-2 幻想乡公库（引擎原生 IO 宝库）修复的完整要素

- **结论**：**可行**。但你实测的两件丢失只是**其中一件的一半** —— 真正的丢法比"补 blockoverride"更严重：**整份替换 `panel_content` 后，那个 block 已经从树上消失，`blockoverride` 找不到目标。** 必须**重建分页按钮 + 重建分页面板本体**（共 2 处），或者放弃整份替换改点状覆盖。另外：**只加 `gold = yes` 玩家仍然不能捐钱**，必须同时给 `unlock_contribute_to_organization_treasury`。

## R1-4 GenericAction 列表能否按条件拆成两组渲染（待验证 6）

- **结论**：**有条件可行**，但它不是"拆成两个 datamodel"，而是 **"同一个 `GetActions` datamodel 实例化两次 + 每项各自 `visible` 过滤"** —— **vanilla 自己就是这么做的**（`laws.gui` 与 `members.gui` 对同一 datamodel 取互斥子集）。因此《UI规格》的"文案前缀分组"退路**成立且零风险**，但**不必退**。

- **语义边界与坑**：
  1. **`texture` 必填**，没有隐式默认。11 条概念 = 11 行 texture（**可以用同一个占位贴图**，vanilla `:295`/`:300` 就是 `flat_icons/_default` + `#TODO`）。
  2. **loc 键必须 `game_concept_` 前缀**。现稿（`TH_审判庭_一级名词TT_v1_2026-10-01.md:29` 等）写的 `th_gensokyo_tribunal_desc:` 是"变量名 + `_desc`"的占位方案，**作为 concept 标题不会被识别**。要么改键名，要么走退路 B。
  3. **alias 也要本地化**（`game_concept_<alias>`），否则命中 alias 时显示原始键。
  4. **默认会进 Europedia**（wiki："By default, all game concepts are shown in the Europedia"）。11 条一级名词进百科是**好事**，但需确认文案风格符合百科语境；若不想要，加 `shown_in_encyclopedia = no`。
  5. **不显示在加载画面**（默认 off），要显示需 `shown_in_loading_screen = yes`。
  6. **`family` 会让父概念的 tooltip 出现在子概念 tooltip 里**（wiki 原文）。11 条一级名词若彼此有从属（如"制裁四档"从属"审判庭"），用 `family` 可以自动串联 —— 但要小心 tooltip 过长。
  7. **游戏内文本不暴露机制**的纪律（《一级名词TT》§0 写作纪律）与 concept 无关，仍需在文案层保证。
  8. **动态值**：concept 的 `_desc` 是**静态 loc**，`$BULLET$` / `#G…#!` / `\n` 可用（同 loc 系统），但 `[X.MakeScope.ScriptValue(...)]` 这类**动态表达式能否出现在 concept desc 里未验证**。**【不确定】** 《一级名词TT》§0 明确要求"数值动态取实时值"——**若 concept desc 不支持动态表达式，则 concept 只能承载静态文案，动态数字仍需走退路 B（tooltipwidget）**。这是本条最需要实机验证的点。
  9. **`GC(arg)` 的 Arg0 是裸 key 字符串**（wiki 原文："accepts the game concept key"）。**【不确定】** 是否可传 `Localize` 结果或带引号形式的差异。
  10. **文件编码**：概念定义 `.txt` 属数据库文件（UTF-8 BOM 惯例）；loc `.yml` 为 UTF-8 BOM + 仅 ASCII 双引号（项目既有约定）。
