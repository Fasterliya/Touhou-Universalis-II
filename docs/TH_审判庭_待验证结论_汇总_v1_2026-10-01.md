## 3. 必须修订的设计文档（**待你批准，我未擅自改 docs**）

### 3.1 【重大】《UI规格》§1.1 / §1.2 —— 面板分流的机制假设被推翻

- **原假设**：三个 IO 共用一个 `organization_panel`，被贤者议会面板整份盖住 → 必须先造分流机制（方案 A/B）。
- **实测机制**：vanilla 是 **`gui/panels/organization/<IO 类型 key>.gui` 一类型一文件**（`theme_templates.gui` 提供 3 个 theme 类型，各文件实例化其一并做点状 `blockoverride`）；`situation` / `disaster` 的官方 readme 把这条约定写成了明文；34 个类型里 32 个有同名文件。
- **推论**：`th_sages_council_io.gui` 的文件名正好等于贤者议会类型 key，**它只作用于贤者议会**；审判庭、人间之里 IO **没有同名文件 → 用 vanilla 默认面板**。§1.1 那句"点开审判庭应该是贤者议会那一套"**大概率不成立**。
- **改写后 T1 前置工程的任务**：不是"造分流"，而是"**给审判庭建一个同名面板文件**"。
- **【用户纠正后的修正 2026-10-01】贤者议会面板不在审判庭的关键路径上**：按一类型一文件机制，`th_sages_council_io.gui` 只作用于贤者议会自己。实测四条 IO 的现状：
  | IO | 同名面板文件 | 实际生效面板 |
  |---|---|---|
  | `th_sages_council_io` | 有（367 行） | 它自己那份（整份替换 `panel_content`） |
  | `th_gensokyo_io` | 有但 177/186 行被注释 | **vanilla 默认面板** |
  | `th_gensokyo_tribunal` | **无** | vanilla 默认面板 |
  | `th_human_village_io` | **无** | vanilla 默认面板 |
  → 因此"要不要把贤者面板改成点状覆盖"是**贤者议会自己的独立议题**，不是 T1 前置，已从拍板清单撤回（原 §4-1）。
- **唯一剩余不确定性**：这条约定没有 PDS 明文（只有同类系统的成文约定 + 命名 1:1 + 合并假设不成立的三重推理）→ 列进 §5 实机必验 1。

### 3.2 《脚本规格》§10.7 / 《UI规格》§5 与 §8-T2⑫ —— 宝库修复的规格升级

- 出处修正：`gold = yes` 在 `catholic_church.txt:30`；`:31-33` 给的是**取款**解锁，**捐款解锁** vanilla 只有 HRE 法律给。
- **【用户纠正后的修正 2026-10-01】工作量大幅下降**：幻想乡 IO **用的是 vanilla 默认面板**（它的同名文件被整份注释），而默认面板的 `organization_panel_treasury_area` 本体仍在树上 —— 所以公库的最小改动是：
  1. 在 `th_gensokyo_io.gui`（现被整份注释的那份，**里面没有现成 treasury 代码，要新写**）加一行 `blockoverride "organization_treasury_tab_visible" { visible = yes }`（照 `hre.gui:2471` 的写法，可带 `enabled = "...IsCurrencyEnabled('gold')"`）；
  2. IO 定义加 `gold = yes`；
  3. 补 `unlock_contribute_to_organization_treasury`（否则玩家仍捐不了钱）。
- R1 报告里"要重建分页按钮 + 分页面板本体两件"的结论，**只在"保留贤者面板整份替换"的路线下成立**；对本项目幻想乡 IO **不适用**。
- 顺带：贤者面板里那行按行动 key 过滤捐款按钮的写法（`th_sages_council_io.gui:313`）只影响贤者议会面板自己，**与公库无关，可不动**。

### 3.3 《脚本规格》§1 铁律 5 —— 删除/修订

原文"`ai_will_do` 上下文不能引用变量"**过度概括**：已证 `io_parliament_bribes.txt:235/251/253` 在 `ai_will_do` 块内使用 `has_variable` 与 `var:`。连带需回改的注释点：§4.1 / §4.2 / §4.7 / §4.8 / §10.1 里所有"照铁律 5，只能用标记"的表述。

### 3.4 《脚本规格》§1 铁律 10 / 铁律 15 —— 补全

- 铁律 10：`international_organization:<tag>` 前缀**只对 `unique = yes` 的类型成立**（官方 `international_organizations\readme.txt:182`）；`international_organization_type:<tag>` 不是 scope 访问器。**本项目四个 IO 全是 unique，故现有写法安全**，但规则要写清。
- 铁律 15：遍历真名是 **`every_in_global_list = { variable = X }`** / `any_in_global_list`（`every_global_variable_list` 不存在）；元素归属判定用 **`owner = scope:X`**（`is_owned_by` 不存在）。

### 3.5 《设计定案》§5.3 第 4 档「限张」—— 名实不符，需改

设计写"扩张花费上浮"，但 **EU5 不存在"领土扩张花费"字段**；项目现有三档"扩张代价修正"实际用的是 `antagonism_received_modifier`（= 承受更多敌意）。三选一见 §4-2。

### 3.6 《脚本规格》§6 / §10.6 —— `previous_owner` 不可跨 6 个月依赖

`previous_owner` 语义是"上一任所有者"（中间二次转手即错），不能当"被扩张前"的权威依据 → **立案时必须快照 `scope:loser`**，观察期末拿快照比对。另：履约条目 3"释放被吞并国家"**只能释放指定国家**（`add_core` + `create_country_from_cores_in_our_locations`），"释放全部"无等价语义 → 语义需收窄。

### 3.7 新增一条检索规程（R3 建议，我赞成）

把 **`in_game\common\trigger_localization\` 与 `effect_localization\`（共 80 个文件）作为"这个触发器/效果到底存不存在"的第一检索入口**写进《脚本规格》§1。本轮两次"字段不存在"的结论都是靠它们定的。
