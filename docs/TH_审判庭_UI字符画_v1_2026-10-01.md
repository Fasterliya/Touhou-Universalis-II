# 审判庭 · UI 字符画合集 v1

> **项目**：Touhou Universalis II（EU5 完全转换 mod）
> **日期**：2026-10-01
> **用途**：把**当前设计定案**下的全部界面画成字符画，作为实现时的对照物与评审依据
> **配套**：`TH_审判庭_UI规格_v1_2026-09-29.md`（元素规格与分档）、`TH_审判庭_设计定案_v1_2026-09-29.md`（机制定案）
> **本文件只画不议** —— 有异议的地方在文末「画图时踩到的疑点」单列，不在图里夹带

## 0. 画图约定

| 项 | 约定 |
|---|---|
| 面板内容宽 | **62 格**（约 470–500 px，与 `gui/panels/organization/th_sages_council_io.gui` 里 470 宽按钮同量级） |
| 中文字宽 | 按 2 格计；`█ ░ • ─ │ ┌` 按 1 格计（**若你的字体把方块/箭头当全角，框线会错位**，换等宽编程字体即可） |
| 数据 | 图中国名、数值均为示意；**数值一律以 script value 动态取实时值**，不写死 |
| 视角 | 每图标注视角（成员 / 阎魔 / 被诉方），因为同一面板三种身份看到的东西不同 |

## 图 6 · 幻想乡 IO 面板（制裁期 · 阎魔视角）

### 6a 宝库分页 —— 原版就有，公库挂在这里

```
总览 │ 成员 │ 法律 │ 宝库 │ 辩论          ← 分页名称示意；「宝库」这一页是原版就有的
                        ↑
              organization_treasury_tab_visible
              （原版默认 visible = no，需各 IO 面板 blockoverride 才出现）

┌─ 宝库 ───────────────────────────────────────────────────────┐
│ 幻想乡公库                                                    │
│                                                              │
│  1,240 金                                                     │
│                                                              │
│ [ 捐款 ]   [ 取款 ]    ← 原生行动 contribute / withdraw        │
│                          金额由原生的 value 选择器输入         │
└──────────────────────────────────────────────────────────────┘
```

**公库不需要自造任何东西**（2026-10-01 回 vanilla 核实）：

- **开启**：`th_gensokyo_io` 定义加一行 **`gold = yes`**（`catholic_church.txt:35`）；
- **UI**：原版 IO 面板自带的**宝库分页**（`common.gui:236-252`，点击切到 `'organizations','treasury'`）—— **零新 GUI**；
- **转账**：脚本侧用 `donate_gold_to_international_organization = { international_organization = X value = Y }`；玩家侧用原生的捐款 / 取款行动 + 原生金额选择器；
- **谁能取钱**：`unlock_withdraw_from_organization_treasury` 决定 —— **这就是"幻想乡公共工程"的天然载体**（HRE 用一条法律解锁捐款，`laws/20_hre.txt`）。

> ⚠️ **但本项目有一个既有缺陷挡在前面**：`th_sages_council_io.gui` 整份替换了 `organization_panel`，**没有保留宝库分页的 block**（原版默认 `visible = no`，必须靠 `blockoverride` 才显示），同时行动列表又把捐款按钮过滤掉了（`th_sages_council_io.gui:313`）→ **玩家现在没有任何途径往 IO 宝库放钱**。开 `gold = yes` 之前必须先补这个 block。详见《脚本规格》§10.7。

## 附 A · 画图时踩到的疑点（需要澄清，但图按我的理解画了）

| # | 疑点 | 图里的处理 | 影响 |
|---|---|---|---|
| 1 | **每次施压是否都要重新提名代理人？** 《脚本规格》§4.2 的描述读起来像"建庭时选一次"，但图 8 画成"每档重新提名" | 按**每档重新提名**画 | 若成立：重档更难找到人肯接（第 3 档邻居可能不敢接），"有人肯替你动手"这道门槛变成**逐档**的，仪式感也更强。若不成立：行动里不需要代理人选择器，流程更省 |
| 2 | 一场制裁同时在案的被诉国是否唯一 | 按**唯一**画（一次一案） | 与审判庭 `unique = yes`、目标标记定位的现有实现一致；若要并行多案，标记法要改成列表法，成本明显上升 |
| 3 | 「宣战（圣战）」按钮由谁点 | 画在成员行动区（保留现状：任何成员可宣战），代理人在 tt 与 AI 权重里优先 | 若改为代理人专属，需拆出第二个行动，且要防误点 |
| 4 | 判决后的"执行清单" | 画成展示性清单 | 它是**存档价值**（玩家能回看自己被怎么判的），也是 T3「结案档案」的入口 |

> 这四条我按最合理的一版画了，但**没有写进设计定案** —— 等你确认后再回写，免得文档和你想的不一样。
