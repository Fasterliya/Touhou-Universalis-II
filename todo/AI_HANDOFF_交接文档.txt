一、项目概述
================================================================================

Touhou Universalis II 是為 Europa Universalis V（EU5，代号Project Caesar）
开发的大型完全转换MOD，将游戏世界替换为东方Project的"幻想乡"（Gensokyo）。

- 游戏时间: 1337.4.1 — 1836.12.31
- 地图: 完全自定义幻想乡大陆 (th_gensokyo_continent)
- 国家: 95个 (T00-T94)，均为东方角色势力
- 所有原版欧洲内容已移除，全部替换为东方世界观

底层框架: CMF (Community Mod Framework, Steam Workshop ID 3692202776)
开发环境: Claude Code + deepseek-v4-pro[1m] (1M上下文窗口)
版本控制: Git (主分支main, 当前活跃分支io)

四、Kasa数据索引脚本（开发工具包）详解
================================================================================

【工具包设计目的】
这是一个专为EU5 MOD开发设计的AI辅助开发环境，配合Claude Code使用。
核心理念：写任何代码之前必须先查维基文档，绝不凭记忆猜测语法。

【开发三阶段质量门禁】
第一阶段 — eu5-preflight（写前）
  自动触发：检测MOD类型关键词 → 查阅MOD类型映射表 → 读取对应维基文档
  → 提取有效字段/已知陷阱/示例 → 将关键语法粘贴进prompt

第二阶段 — eu5-review（写后）
  每个文件10项检查：编码、括号配对、字段名合法性、铁律对照、
  作用域链、本地化key、事件ID、CMF集成、覆盖语法、结构完整性

第三阶段 — eu5-audit（最终）
  7阶段全量扫描：编码 → 本地化 → 事件ID → 修饰符引用 →
  CMF注册 → 括号配对 → error.log关联

【Agent使用规则（来自CLAUDE.md）】
1. Agent spawn必须传 "model": "opus"（否则1M上下文不生效）
2. Agent只用于读操作（探索/研究/审计），写代码由主进程完成
3. 必须派agent写文件时：任务≤2个文件、所有参考语法贴入prompt、附加防卡死规则
4. Explore agent最佳用于并行搜索base game/维基
5. 模型: deepseek-v4-pro[1m]（1M token上下文）

【维基代码库7分类结构】
一_文献资料: Effect/Trigger/Scope/Variable/OnActions/Localization/ScriptValue/
             ModifierTypes/GUI语法/交叉验证铁律/Macro/Color/Defines/MTTH
二_剧情内容: Event/Situation/Disaster/Mission/Action/Setup/Modifier/ScriptedGUI
三_脚本类型: 41篇涵盖所有游戏对象系统
四_地图与图形: Map/Terrain/Flag
五_GUI与界面: 13篇GUI语法标准 + 硬编码边界
六_MOD管理与调试: MOD结构/编码规范/控制台命令/兼容性/存档编辑

【MOD类型→文档自动映射机制】
当用户消息包含MOD创建/修改关键词时自动触发：
1. 读取 MOD类型_维基文档映射.md
2. 根据MOD类型获取 REQUIRED + OPTIONAL 文档清单
3. 读完REQUIRED文档的关键语法后开始写代码
4. Agent spawn时相关文档的关键语法贴入prompt

高频映射示例：
- buff/修饰符 → Modifier_types + Modifier_modding
- 事件/event → Event_modding + On_actions
- 局势/situation → Situation_modding + On_actions
- 建筑/building → Buildings_modding
- 国家/country → Country_modding + Country_ranks
- IO/国际组织 → International_organization_modding
- GUI/界面 → GUI_script + GUI硬编码边界 + Interface_modding_guide

================================================================================
五、EU5游戏脚本语法速查
================================================================================

【基础语法】
key = value                  # 基本赋值
nested_block = {             # 嵌套块使用花括号
    inner_key = 123
}
# 以 # 开头为注释

【值类型】
- 布尔: yes / no
- 整数: 5, -10, 1000
- 浮点: 0.5, -0.1
- 字符串: "text" 或裸标识符 some_text
- 颜色: rgb { 40 40 40 } 或 hsv360 { 360 100 100 }
- 日期: 1337.4.1（年.月.日）
- 作用域引用: c:PAP, government_type:republic, religion:catholic
- 修饰符引用: modifier:block_from_change_to_empire_rank

【脚本触发器（conditions）】
定义在 common/scripted_triggers/，可重用条件：
  my_trigger = {
      OR = { prestige > 70  total_population > 2000 }
      is_subject = no
  }
带参数: $variable$ 语法
  my_trigger = { value = 12 }

【脚本效果（effects/commands）】
定义在 common/scripted_effects/：
  my_effect = {
      add_prestige = 10
      every_owned_location = { add_building = building:marketplace }
  }

【脚本值（数学计算）】
定义在 common/script_values/：
  my_value = {
      value = 100
      multiply = 1.5
      if = { limit = { ... }  multiply = 2.5 }
      min = 0
  }

【事件格式】
  namespace = my_event_set
  my_event_set.1 = {
      type = country_event    # 或 location_event/unit_event/age_event
      title = my_event_set.1.title
      desc = my_event_set.1.desc
      trigger = { ... }
      immediate = { ... }
      option = {
          name = my_event_set.1.a
          ai_will_select = { value = 1000 }
          # 效果
      }
  }

【国际组织（IO）】
  my_io = {
      type = international_organization
      # 四级修正层级:
      #   modifier          — 所有成员
      #   non_leader_modifier — 非领袖成员
      #   leader_modifier   — 领袖
      #   IO_modifier       — IO本身（用th_gensokyo_io作用域）
      leader_change_method = vote  # 或 hereditary/score/none
      parliament = { ... }  # 议会系统（投票权重等）
  }

【国家互动（country_interaction）— 当前正在修改的系统】
新版格式（正在迁移中）：
  my_interaction = {
      scope = country
      is_shown = { ... }      # 是否可见
      is_valid = { ... }      # 是否可执行
      effect = { ... }        # 执行效果
      notification_key = ...  # 通知本地化key
  }
旧版格式（已注释）：
  my_interaction = {
      type = diplomacy
      category = CATEGORY_FRIENDLY_ACTIONS
      potential = { ... }
      allow = { ... }
      effect = { ... }
      ai_will_do = { value = 0 }
  }

【覆盖语法】
五种模式: REPLACE / INJECT / REPLACE_OR_CREATE / TRY_REPLACE / TRY_INJECT

【编码规则 ★★★ 非常重要】
- .yml / .txt（游戏数据文件）→ UTF-8 BOM
- .gui / .csv → 无BOM
- 本地化文件名格式: xxx_l_simp_chinese.yml
- 事件ID格式: namespace.integer（integer 1-9999）
- 本地化key格式: th_<范围>_<键值>_<后缀>（如 th_BA1_dover_fort.title）

【命名约定】
- 所有幻想乡内容: th_gensokyo_ 或 th_ 前缀
- 国家标签: T00-T94
- 地点: th_ 前缀 + snake_case
- 字体/立绘: touhou_ 前缀（角色名）
- 文化: th_ 前缀 + 描述性名称

【文件架构：三层上下文系统】
EU5将数据分为三个上下文层（与EU4完全不同）：
1. in_game/  — 核心游戏数据
2. main_menu/ — 主菜单数据（成就/纹章/设置/静态修正）
3. loading_screen/ — 加载画面数据（定义常量/字体/图形）

MOD必须镜像此结构。

================================================================================
六、开发工作流与铁律
================================================================================

【铁律（来自kasa CLAUDE.md）】
1. EU5 ≠ EU4，语法完全不同，绝对禁止混入EU4代码/字段/结构
2. 未查维基/文档前禁止写代码——凭记忆写 = 编造
3. 不确定的字段/语法 → 查维基 → 查官方readme → 查base game → 绝不猜测
4. 写MOD前必须先读目标系统的readme和base game源文件
5. 读到引用必须深扒key定义——功能链（引用→定义→实际效果）三步走完
6. 所有.yml/.txt必须UTF-8 BOM
7. 事件ID必须 namespace.integer 格式（integer 1-9999）
8. 使用CMF（Community Mod Framework）作为底层框架
9. 本地化key需要 th_ 范围前缀避免冲突

【标准开发流程】
1. 确认MOD上下文（在哪个MOD上工作？源文件在哪？目标playset？）
2. 打开维基索引 → 找到目标系统的文档 → 读完
3. 维基有 → 按文档字段和示例写
4. 维基没有 → 查官方 common/<系统>/readme.txt
5. readme也没有 → 查优秀MOD参考中的同类文件
6. 仍不确定 → 读base game同名文件对照
7. 绝不猜测字段名

- SessionStart: 验证环境路径
- PreWrite: 文件备份（保留最近50个）
- PostWrite: UTF-8 BOM检查、括号配对检查、同步到游戏目录、编辑日志
